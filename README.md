# HANA LOG

ニューキングハナハナV-30の実戦を記録する、iPhone向けのオフラインPWA。React + TypeScript + Viteで実装しています。バックエンド、ログイン、外部API、設定分析はありません。

## 起動と検証

Node.js 22.12以上（この環境では24.22.1）とnpmを使用します。

```sh
cd /workspace/hana-log
npm ci
npm run dev
```

開発サーバーは5173番ポートです。PWAは本番ビルドでのみ有効になります。

```sh
npm test                # 計算・データ検証の自動テスト
npm run build           # TypeScriptチェック・本番ビルド・SWのバージョン生成
npm run preview         # 本番ビルドを4173番ポートで確認
```

ブラウザ統合テスト：

```sh
# 初回のみ。ブラウザが未導入なら実行
npx playwright install chromium
# 環境のChromiumパスを指定（このクラウドでは /usr/bin/chromium）
CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
# Playwrightのブラウザを使う場合はインストール先の実行ファイルをCHROMIUM_PATHに指定
```

統合テストはビルド済みの`dist`を起動し、390pxのモバイルChromiumで検証します。iPhone Safari実機のテストではありません。ポート4173を使用中の場合は先に停止してください。

## 使い方

1. 「はじめの実戦を記録」から店舗・台番号・着席時データを入力します。入力途中の開始フォームも保存します。
2. 現在の当選間Gを入力し、当選時にBIGまたはREGをタップします。すぐに仮登録され、当選間Gは0へ戻ります。
3. 当選履歴または未確定の案内をタップし、自然スイカ・ランプ・レトロ情報を入力します。各操作で保存されるため、詳細確定前に画面を閉じても残ります。「詳細を確定する」は同じ履歴の状態を変更し、ボーナスを追加しません。
4. ベルは＋1、−1、数字タップによる累計値の直接入力を併用できます。
5. 履歴をタップすると当選間G、種別、詳細を修正・削除できます。種別変更時は確認後に機種固有情報を未記録へ戻します。累計は履歴から再計算します。
6. 投資額・貯メダル・回収枚数は追加額ではなく累計額を直接入力します。
7. 「ChatGPTに共有」で簡易／詳細のテキストをコピーできます。クリップボードが許可されない環境ではテキスト欄を長押ししてコピーしてください。ChatGPTへの送信自体は行いません。
8. 「実戦を終了する」で最終ハマリGを入力します。終了後も履歴修正が可能です。通常の登録を再開する場合は「終了内容を確認」→「この実戦を再開する」。台移動は「新規実戦」を使い、以前の台は「実戦一覧」で切り替えます。
9. 「取り消し」は現在のページでの直近20操作（詳細の各入力を含む）を戻します。ページを閉じると取り消し履歴は失われますが、実戦記録は残ります。

## ゲーム数の定義・仮定

着席時の「台の総ゲーム数」は**現在の未当選区間を含む通常時の累計**です。ボーナス消化Gは含めません。ホールの表示が異なる場合は換算して入力してください。「現在の当選間G」は直前ボーナスからの区間で、他人が回した区間も含みます。

```text
台累計 = 着席時総G − 着席時当選間G + 各当選間Gの合計 + 現在の当選間G
自分の通常時G = 台累計 − 着席時総G
台BIG/REG = 着席時の既存回数 + この実戦の履歴件数
```

例：総1,000G・当選間200Gで着席し、350Gで初当選したら、台累計1,150G・自分150Gです。400Gの途中保存後に550Gで当選しても550Gだけを採用します。5,765Gの当選累計から284Gヤメで6,049Gになります。過去の当選間Gは「前回ボーナスからの区間」として編集します。削除するとその区間も集計対象から外れます。取りこぼした別区間を補う必要がある場合は、残す履歴の区間を実測に基づいて修正してください。

ベル・スイカ・ランプ・レトロは**自分の実戦分だけ**です。未入力は`null`で保持し、0・白・なしとは区別します。自然スイカのみを記録し、技術介入スイカは加算しません。レトロ権利の有無は自動推定しません。REGにサイドランプはありません。

## 保存とバックアップ

- `localStorage`へ入力ごとに同期的に保存します。軽量なテキスト記録に絞り、IndexedDBなどの非同期書き込み完了前にアプリを閉じる問題を避けています。
- 別のタブでの変更を検知した場合は上書きを停止します。同時編集は避け、警告時は必要な記録をJSONで退避して再読み込みしてください。
- 保存失敗時は警告を出し、その操作を画面へ反映しません。再読み込み後の破損データ検出時は上書きを停止します。復元機能は利用できます。
- 設定の「全実戦をJSONで保存」でファイルを「ファイル」アプリ等に退避してください。「JSONバックアップから復元」は形式・数値・機種・ランプ・IDを検証し、確認後に全実戦を置き換えます。復元前にもバックアップを推奨します。
- ブラウザの保存は端末故障、サイトデータ削除、容量制限、OSによる消去を完全には防げません。プライベートブラウズは避けてください。永続ストレージも対応するブラウザへ要求しますが、許可は保証されません。
- 保存先はオリジンごとに異なります。開発サーバー・公開先・ドメインの変更時はJSONで移行してください。Safariとホーム画面アプリ間でも共有されると仮定せず、必要ならJSONで移行してください。
- データ読み込みエラー時に出力するJSONは現在メモリ内で読めた分だけです。元の破損文字列は上書きしません。データ復旧が必要な場合は開発者ツール等で元のストレージを保全してください。

## iPhoneへの導入・公開

1. `npm run build`を実行し、`dist/`を静的ホスティングへ公開します。Cloudflare Pagesならビルドコマンド`npm run build`、出力ディレクトリ`dist`を指定します。GitHub Pagesでも`dist`をデプロイできます。相対ベースのためサブディレクトリ配信にも対応します。Node依存のサーバーは不要です。
2. 公開先はHTTPSが必須です。iPhone SafariでURLを開きます。PCのローカルアドレスをiPhoneで開いただけでは通常PWAのオフライン機能は有効になりません。
3. ページ下部の「オフライン準備完了」を確認します。Safariの共有メニュー→「ホーム画面に追加」→「追加」。
4. ホーム画面から起動し、最初はオンラインで読み込んでから機内モードで起動・登録・再起動を確認してください。
5. アプリ更新時は開いているアプリのウィンドウをすべて閉じ、オンラインで再度開きます。Service Workerはビルド内容に応じたキャッシュを作成します。更新は既存ウィンドウを強制再読み込みしません。

この作業では外部サイトへのデプロイやiPhone実機検証は行っていません。iPhone Safariのキーボード、ホーム画面追加、操作時間（仮登録5秒・詳細10秒）、OS終了後の復元は実機確認が必要です。

## ファイル構成

```text
src/model.ts          データ型・機種別入力設定・履歴登録・累計計算・共有・復元検証
src/storage.ts        同期保存・読み込み・JSON出力
src/App.tsx           メイン画面・実戦一覧・ボトムシート・編集・取り消し
src/style.css         ダークUI・iPhone向けレスポンシブ・セーフエリア
src/model.test.ts     計算とバックアップのユニットテスト
src/main.tsx          React起動・本番SW登録
public/               マニフェスト・アイコン・オフラインSW
scripts/version-sw.mjs ビルドごとのSWキャッシュバージョン
playwright.config.ts  モバイルChromium検証設定
tests/app.spec.ts     保存・オフライン・復元などのブラウザテスト
```

拡張時は`model.ts`の`machine`を機種IDに対応する設定レジストリへ拡張し、入力可能な色・項目を機種ごとに切り替えます。現在のMVPはニューキングVだけを選択可能にしています。

## 検証について

UI・計算・保存の自動検証はリポジトリ内のテストを参照してください。クラウド同期・分析・他機種・外部データ取得はMVPに含めません。
